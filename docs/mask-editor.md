# 部位定義の編集ツール

## 目的と対象

1025種類の元画像から、頭の範囲・接続点・補完領域・配色・保護領域を手作業で指定する開発用画面を用意しました。定義済みの386種類も編集できます。定義の追加後は、生成した頭と体、異種との合成を目視で確認します。

## 起動と編集

`pnpm dev`を起動し、`/tools/mask-editor/`を開きます。通常の製品ビルドにはこの画面を含めません。全国図鑑の1025種類から番号・名前で対象を探し、元画像を拡大して表示します。対象を変えると編集中の内容は破棄されるので、先にJSONを保存してください。

クリックの用途を選び、頭の多角形、頭・体の接続点、頭・体の皮膚色、補完領域と体の保護領域を入力します。頭の多角形は点を追加するたびに線で表示します。名前や配色が未入力でも作図できます。「頭の最後の点を削除」で、多角形の末尾の点を1つ削除できます。クリックの用途が別の項目でも、削除するのは頭の多角形の点だけです。空の多角形や不正なJSON・作図情報ではボタンを無効にします。途中の点の削除はJSON欄で行います。多角形と接続点は画像の座標、色はクリックした可視ピクセルのRGBです。

補完領域は「体の補完領域に点を追加」を選び、「補完色」で塗る色を指定して元画像を3点以上クリックします。「補完領域を追加」で既存の補完領域に1つ追加し、体のプレビューに反映します。入力中の点は赤線で表示します。補完色は初期値が灰色で、保存するRGBAの透明度は255です。指定した範囲を補完色で埋め、頭の外にある元画像の可視ピクセルはその上に残します。補完色を配色変換の対象にする場合は、体の皮膚色にもそのRGBを指定してください。入力中は保存を無効にし、用途・対象の変更やJSON欄の編集で未確定の点を破棄します。補完領域の修正・削除はJSON欄で行います。

保護領域は「クリックの用途」で「体の保護領域に点を追加」を選び、元画像を3点以上クリックしてから「保護領域を追加」で確定します。入力中の点も紫線で表示します。確定すると既存の保護領域に1つ追加し、配色の検証に反映します。入力中はJSON保存を無効にします。用途・対象の変更やJSON欄の編集で、未確定の点を破棄します。既存の保護領域の修正・削除はJSON欄で行います。

接続幅、合体名の前半・後半もJSON欄で変更します。JSON全体を編集でき、変更は頭・体のプレビューに反映します。

頭は3点以上の多角形、配色は頭2色以上・体1色以上が必要です。色は実際の対象領域に存在するものを指定します。不正なJSON、範囲外の座標、存在しない指定色や空の部位はエラーにして、保存を無効にします。画像読込に失敗した場合も保存できません。前の対象の遅い読込結果は表示しません。

## 保存と素材生成

マスクの定義を`src/data/fusion-masks.json`に保存します。画面はリポジトリへ直接書き込まず、検証済みの1種類分をJSONとしてダウンロードします。

```bash
pnpm import:mask /path/to/fusion-mask-7.json
pnpm prepare:fusion
pnpm validate:fusion
pnpm test
pnpm build
```

取込は同じ図鑑番号の定義を置き換え、新しい番号なら追加します。取込対象と既存定義の構造、番号の重複、元画像に対する切出しと配色を検証してから定義ファイルを更新します。失敗した場合は定義ファイルを変更しません。生成物の更新は別のコマンドで行い、差分を確認します。

## 確認項目

既存6種類の定義・生成ピクセルが変わらないこと、範囲外の番号や不正な構造を拒否すること、失敗した取込で定義ファイルを保つことを自動確認します。編集画面では1025件の選択、座標・色の入力、プレビュー、保存の制御と幅360pxの表示を確認します。

現在の対応数は第1〜第3世代の386種類です。残る639種類は、このツールで部位を定義し、合成結果を調整する必要があります。

## 確認結果

- TDDで未実装の検証・取込・編集画面のテストが失敗することを確認し、実装後は全77件が成功しました。
- 型検査、製品ビルド、1025種類のデータ検証と既存6種類の部位検証が成功しました。製品ビルドには編集画面のファイルを出力していません。
- Edgeで1025件の一覧、全角番号による検索、1025番の選択、画像座標とRGBの入力、頭・体のプレビュー、JSONのダウンロードを確認しました。
- ダウンロードしたJSONを実際に取り込み、素材を再生成しました。既存6種類のPNGと接続・配色情報に変更はありません。
- 不正JSONと元画像の読込失敗では保存を無効にします。遅い読込結果を対象変更後に反映しないことは画面テストで確認しました。
- 幅360px・1280pxで横方向のはみ出しはありませんでした。Tabキーで選択欄へ移動し、フォーカス表示を確認しました。通常文字・操作欄・エラー表示の文字コントラスト比は最小約6.7対1で、実行時のJavaScript例外はありませんでした。
- Firefoxは開発環境のプロファイル制約で未確認です。全種対応版のリリース前に確認します。

頭の最後の点を削除する操作は、追加した点を1つ戻せること、他の項目を変更しないこと、3点未満でプレビュー・保存を無効にすること、空や不正なJSONで削除を無効にすることを画面テストで確認しました。追加テストが未実装で失敗することを確認した後、全78件のテスト、型検査とビルドが成功しました。ボタンには既存の配色とフォーカス表示を使っています。

体の保護領域のクリック入力では、既存領域への追加と、指定した皮膚色のピクセルが変換対象から外れることを画面テストで確認しました。未確定の点をJSONに含めず保存を止めること、用途・対象・JSONの変更で破棄することも確認しています。追加した2件のテストが未実装で失敗することを確認した後、全80件のテスト、型検査とビルドが成功しました。Edgeでも紫線の描画、入力座標の反映、Enterキーによる確定を確認しました。幅360px・1280pxで横方向のはみ出しはなく、操作欄と説明文の文字コントラスト比は最小約7.2対1、実行時のJavaScript例外はありませんでした。

補完領域のクリック入力では、指定したRGBと透明度255で体の透明部分を埋め、頭のピクセルを変更しないことを確認しました。未確定点の保存停止と、用途・JSON・対象の変更時の破棄も画面テストで確認しています。追加した2件のテストが未実装で失敗することを確認した後、全82件のテスト、型検査とビルドが成功しました。Edgeで赤線の作図、補完色の入力、Enterキーによる確定と体プレビューへの反映を確認しました。幅360px・1280pxで横方向のはみ出しはなく、操作欄と説明文の文字コントラスト比は最小約7.2対1、実行時のJavaScript例外はありませんでした。
