# 実装仕様と開発手順

この資料は、1025種類の合体ポケモン生成機を実装するための仕様です。1025種類の一覧と元画像を準備し、6種類の部位素材・Canvas合成・検索・ランダム選択・左右交換・皮膚色の変換を実装しました。全種の部位・配色の定義と品質調整は今後の作業です。元サイトで確認した事実は[調査資料](fusion-research.md)、起動と確認の手順は[開発環境](development.md)を参照してください。

## 確定事項と検証する案

AGENTS.mdに基づき、React・TypeScriptでブラウザ上のアプリケーションを実装し、pnpmで依存関係を管理します。対象は全国図鑑No.0001〜1025です。

初期仕様では各種の基本形を扱い、リージョンフォーム、メガシンカ、姿違い、色違いは後の拡張対象とします。左を頭、右を体として区別し、同種同士も選択できます。全種対応時の組み合わせは1,050,625通りです。

ブラウザのCanvasによる画像合成を6種類で試作しています。元画像はPokeAPI/spritesの96×96ピクセルのドット絵系列です。皮膚色は種ごとの配色と対象領域を使って変換します。全種の部位の切り分けと配色の定義は未完了です。少数の種で画質を確認してから広げ、成立しなければ、この資料を更新して方式を見直します。

全種の部位整備には[部位定義の編集ツール](mask-editor.md)を使います。最初の6種類の部位定義、素材生成と合成規則は[画像合成の試作](fusion-prototype.md)に記載します。

6種類を選ぶ検索・ランダム・交換の動作は[試作の操作画面](selection-ui.md)に記載します。

6種類の皮膚色と保護領域を使う配色変換は[体の配色を頭に合わせる試作](color-matching.md)に記載します。

## 技術構成

| 用途 | 使用するもの・方針 |
| --- | --- |
| 画面 | React・TypeScript |
| パッケージ管理 | pnpm。実装時にバージョンをpackage.jsonのpackageManagerに記録し、pnpm-lock.yamlを管理する |
| 開発サーバー・ビルド | ViteのReact・TypeScript構成 |
| 状態管理 | Reactのstateで選択番号、検索語、読み込み状態を管理する |
| 表示の調整 | CSS。配色、余白、文字サイズを共通のCSS変数で定義する |
| 合成 | Canvas 2D。座標計算と名前生成は画面から独立したTypeScriptの関数にする |
| 自動テスト | Vitest。画面操作のテストにはReact Testing Libraryを使う |
| 配信 | ビルドした静的ファイルと、同じ配信元に置くデータ・画像 |

開発環境はNode.js 26以上、pnpm 12.11.2を前提とします。依存パッケージはpackage.jsonとpnpm-lock.yamlに記録し、型検査・テスト・ビルドで組み合わせを確認します。Node.jsの要件は採用したVitestとjsdomの対応範囲に合わせています。

初期実装は1画面とし、データ準備は開発用の処理で行います。閲覧時の合体に外部の画像生成サービスは使いません。

現在の画面では6種類から頭と体を選び、合成結果を表示します。検索・ランダム選択・左右交換で組み合わせを変えられ、体の皮膚色を頭に合わせる切り替えもできます。形と配色は調整中で、1025種類への対応は準備中であることを伝えます。

## データ準備

全国図鑑番号を種の識別子に使います。数値で保存し、表示時だけ4桁に整えます。種名・世代・基本形の対応はPokéAPIの公開CSVから取得し、番号1〜1025を明示的に対象にします。取得元の全件数をそのまま対象数として使いません。取得元と検証の詳細は[データ準備](data-preparation.md)に記載します。

種のデータから日本語名と世代を取得し、pokemon.csvの`is_default=1`のポケモンを元画像の対応先として確認します。これは種別APIの`varieties`に対応する基本形の指定です。種の番号と姿違いのポケモンIDを混同しません。CSV上の日本語名は`ja-hrkt`を優先し、なければ`ja`を確認します。両方ない場合は不足として報告します。

各種に持たせる情報は次のとおりです。

| 情報 | 用途・検証条件 |
| --- | --- |
| 図鑑番号 | 1〜1025の整数。全種対応時は欠番・重複がないこと |
| 日本語名、世代 | 検索と表示。名前は空文字を認めない |
| 合体名の前半・後半 | 独自に設定する。単純な文字数の中央分割は仮データに限り、公開前に見直す |
| 元画像のパス | 同種同士の結果と、選択したポケモンの表示 |
| 頭・体素材のパス | 切り出した頭と、元の頭を除去・補完した体の透過PNG |
| 素材の寸法と接続点 | 接続点は各素材の左上を原点とするピクセル座標 |
| 接続幅 | 頭と体の倍率合わせに使う正の値 |
| 配色情報 | 配色変換を採用する段階で定義する。変換対象と保持する領域を区別する |

元画像の候補は[PokeAPI/sprites](https://github.com/PokeAPI/sprites)です。採用系列を決める前に、1025種類のファイルの存在、画像としての読み込み、寸法、透過、画風、出典と利用条件を確認します。別系列を混ぜる場合も、合成結果の品質を確認してから採用します。

取得結果はローカルに保存し、取得元URLと取得した版・日時を記録します。通常の閲覧時にPokéAPIへアクセスしません。部位素材は元画像と独自のマスク・補完情報から準備する案とし、マスクと生成済み素材が食い違わないよう、生成元も管理します。

データ準備で不足や不正な座標が見つかった場合は、対象の番号と理由を出して処理を失敗させます。試作では対象を明示した少数の種を検証し、全種対応の検証では1025種類すべてを要求します。元画像をそのまま合体結果に流用して、未対応の組み合わせを成功扱いにはしません。

## 合成の動作

同種同士の場合は元画像と元の名前を表示します。異なる種の場合は、左の名前の前半と右の名前の後半を連結し、左の頭素材と右の体素材を合成します。

頭素材の接続幅に対する体素材の接続幅の比から頭の倍率を求め、両方の接続点が一致するように配置する案です。合成した素材全体の範囲を計算し、出力領域に収まるよう全体を同じ倍率で調整します。出力寸法と余白は試作の目視結果をもとに決めます。素材の切り落としや、頭と体それぞれの縦横比の変更で収める処理は使いません。

体を先に描き、その上に頭を描く方式から検証します。前景に置く必要がある腕や装飾などは試作で確認し、必要な場合にだけ素材や描画順の仕様を追加します。ドット絵を採用する場合は画像の補間を無効にし、表示側でもピクセルの輪郭を保ちます。

配色変換は6種類で試作しています。皮膚色を明暗順に置換し、透過と保護領域を維持します。配色の段階が減る場合や、皮膚と同じRGBを使う模様の扱いは品質調整の対象です。詳しい規則と比較画像は[配色の試作](color-matching.md)を参照してください。

頭と体が一体の種、複数の頭を持つ種、蛇型などは一律の切り分けで処理できると仮定しません。各種の素材を調整し、対応方法が決まらない場合は未対応として記録します。

## 画面の動作

左右の選択欄には「頭」「体」と表示し、図鑑番号、日本語名、元画像を確認できるようにします。結果欄には合体名と合体画像を表示します。初期選択はNo.0001とNo.0004とし、選択の変更時に結果を更新します。

| 操作・状態 | 動作 |
| --- | --- |
| 名前検索 | 前後の空白を除き、NFKC正規化とひらがな・カタカナの表記統一をした名前の部分一致で絞る |
| 番号検索 | 数字だけの検索語は図鑑番号の完全一致とする。0001と1を同じ番号として扱う |
| 検索語が空 | 選択可能な全件を図鑑番号順で表示する |
| 検索結果が0件 | 該当なしと表示し、現在の選択は変更しない |
| ランダム | 左だけ、右だけ、両方の操作を用意する。検索語に関係なく選択可能な全件から選ぶ。同種同士も許す |
| 左右交換 | 頭と体の番号を交換し、名前と画像を再計算する |
| 読み込み中 | 処理中と表示する。選択操作は続けられる |
| 画像読み込み・合成の失敗 | 現在の組み合わせの失敗を表示し、再試行できるようにする |
| 連続して選択を変更 | 最後の選択に対応する結果だけを反映する。古い処理の結果や失敗で上書きしない |

選択が変わった時点で前の結果を消し、別の組み合わせの名前と画像が並ばないようにします。全種対応版では全1025種類を選択可能にします。試作では対応した種だけを選択可能とし、試作であることと対象数を表示します。

操作にはbutton、入力欄にはラベルを使います。検索結果からの選択と左右交換はキーボードでも行えるようにし、読み込み状態とエラーは読み上げ可能にします。画像には種名または合体名を伝える代替テキストを付けます。

## テスト方針

各開発段階で資料を更新し、期待する動作のテストを書いて失敗を確認してから、最小実装で通します。資料だけを変更する段階では、本文・リンク・差分を確認します。

| 対象 | 確認する振る舞い |
| --- | --- |
| データ | 試作の対象一覧、全種対応時の1〜1025の網羅、不足・重複・範囲外・素材欠落・接続幅と座標の不正を検出する |
| 名前・検索 | 前半と後半の連結、同種同士の元名、かな・半角の正規化、番号検索、空検索、0件 |
| ランダム・交換 | 乱数を差し替えて先頭・末尾の選択を確認する。対象外を返さず、交換を2回行うと元の選択に戻る |
| 合成 | 小さな透過画像を使い、接続位置、描画順、全体の収まり、元画像を変更しないことを確認する |
| 画面 | 検索からの選択、左右交換、処理中、失敗と再試行、遅れて完了した古い処理を反映しないことを確認する |

Canvas描画は実際のブラウザでも確認します。描画APIを置き換えたテストだけで画像の正しさを判断しません。最初は同種同士、通常の頭・体、蛇型、頭と体が一体の種、複数の頭を持つ種を試し、採用した種の左右の組み合わせを目視で確認します。

## 開発手順

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| 1. 開発基盤 | Vite・React・TypeScript・pnpmとテスト環境を用意する | 簡単な画面のテスト、型検査、ビルドを実行できる |
| 2. データ準備 | 取得・検証処理をTDDで実装し、元データと画像を確認する | 名前と元画像の1025種類分の不足一覧を出せる。全件が揃ったか明記する |
| 3. 合成の試作 | 代表的な形状の少数の種で部位素材と合成処理を作る | 接続と透過のテストが通り、左右を含む試作画像の品質を確認できる |
| 4. 操作画面 | 試作データで検索・ランダム・交換・状態表示を実装する | 表に定めた画面の動作をテストとブラウザで確認できる |
| 5. 全種への拡張 | 1025種類の部位素材・名前分割を整備し、配色を調整する | 全種のデータと素材が検証を通り、各種が頭・体の両方として合成できる |
| 6. リリース確認 | テスト・テーマ診断・差分チェックを行う | 次節の条件を満たし、残る品質上の制約を資料に記録する |

各段階で不要コードと資料の矛盾を確認します。1025種類の名前や元画像が揃った段階では、1025種類の合体対応完了とはしません。

## リリース前の確認

`pnpm test`、`pnpm typecheck`、`pnpm build`、`pnpm preview`は開発基盤で用意しています。`pnpm test`は監視なしで終了する自動テストです。`pnpm validate:data`は全種の一覧と元画像、`pnpm validate:fusion`は6種類の部位素材と接続情報を検証します。配信確認には`pnpm preview`を使い、`git diff --check`で変更したファイルの差分を確認します。新規ファイルも空白・リンクの検査対象にします。

このプロジェクトでのテーマ診断は、画面の配色と表示・操作の確認とします。幅360pxのスマートフォン相当と1280pxのデスクトップ相当で、横方向のはみ出し、選択欄と結果の読みやすさ、文字と背景のコントラスト、フォーカス表示、ドット絵の輪郭を確認します。検索0件、処理中、失敗時も同じ条件で確認します。Chrome系とFirefox、モバイル相当の画面で動作を確認します。

全種の素材検証に加え、各種について頭として使う例と体として使う例を確認し、形状ごとの代表的な組み合わせは目視で点検します。この確認は約105万通りすべての画質保証ではないため、確認した組み合わせと未解決の制約を記録します。素材不足や未対応の種が残る場合は、1025種類対応としてリリースしません。

更新履歴はREADME.mdとchangelog.mdに同じ内容を追記します。コミットは行いません。
